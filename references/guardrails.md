# 护栏、验收门与止损

> 多 Agent 协作的失败，几乎都不是「模型不够聪明」，而是边界没定。写权、验收标准、回滚路径必须提前写死。

## G1 · 写权与分支控制

- 一卡一分支 `agent/T-xxx`：分支推到远端即视为认领，别人看到就换卡。
- 禁止直推 main，开保护规则：至少一次评审、必须构建通过。
- push 被拒先 fetch + rebase，不许 force push 覆盖他人提交。
- 同一个文件同一时间只归一个分支；跨席位改动先拆卡。

## G2 · 验收门（DoD）

解决「算不算做完」，标准写死，不许各说各话。六条全过才算这张卡结束：

| # | 检查项 | 自动化 |
| --- | --- | --- |
| 1 | 构建通过（本分支本次改动后跑的） | `relay-verify.sh` 执行任务卡 frontmatter 的 acceptance 命令 |
| 2 | 测试通过 | 同上 |
| 3 | lint 无新增问题 | 同上 |
| 4 | 改动范围 = 任务卡范围 | `git diff --name-only origin/main...HEAD` 与 allowed_paths 比对 |
| 5 | 分支与交接单已推送 | HEAD == upstream、交接单在 HEAD 树内、last_commit == 绿色提交 |
| 6 | 无密钥 / 调试残留 | diff 中新增行的 key/private-key/console.log/debugger 扫描 |

三条命令必须是**本次改动之后**跑的；改码前的绿色构建不算数。任何一条没过，`relay-verify.sh` 退出非 0，不许写 `status=handoff`。

## G3 · 失败与回滚

- 接手方复现失败：checkout 交接单里的提交号，别从 main 猜现状。
- 分支落后太多：先 `rebase origin/main`，再跑验收命令。
- 两个分支改了同一文件：合并在先，人工裁决冲突，不许强推覆盖。
- 任务卡本身有歧义：退回产品席改写，实现席不许自行发挥。

## Fail Fast · 接不下去时怎么办

1. 先停写，别在红的基线上继续叠改动。
2. 回退到上一个绿色提交，保留现场。
3. 把失败复现步骤写进交接单。
4. 拆小任务卡，重新派单给另一个席位。

> 回滚不是失败，带着错误往前走才是。

## 人工介入阈值（human-in-the-loop）

出现任一情形，写 `status=blocked` 并在交接单 / log 里明确 @人：

- `verify_fail ≥ 3` 次（同一张卡）；
- 写不出验收命令，或任务卡本身有歧义；
- 涉及生产凭据、数据迁移、 irreversible 操作；
- 同一文件冲突两个席位无法裁决；
- 软交接重绑时发现仓库与聊天记录不一致且无法判断哪个是事实。

## 信号 → 处置对照

| 风险 | 可观测信号 | 处置动作 |
| --- | --- | --- |
| 看的是过期代码 | 本地很久没 fetch，分支落后 main 一大截 | 开工和交接前都 `git fetch --all --prune`，以远端为准 |
| 两个克隆抢同一张卡 | push 提示远程分支已存在 | 让出这张卡，或拆卡另开分支；不要改名硬挤 |
| 直接改 main，回滚很难 | main 出现没有评审的提交 | 立即 revert，补齐 main 保护规则 |
| 交接单留在本地 | 下一棒 fetch 不到 handoff 文件 | 交接单和代码放进同一次 push，再宣布交接 |
| 构建一直红，没人敢接 | 连续两棒都没让分支变绿 | 降级为最小修复卡，只修构建，别的都不做 |
| 换模型后沿用旧结论 | 新模型跳过 state.json 直接改文件 | 强制先读仓库三件套并复述约束四行后才能动手 |
| 小窗口丢约束 | 早期 allowed_paths / 验收命令在新会话里消失 | 换模型前压交接单 + 重述约束；必要时转硬交接 |

## 六种反模式

| # | 反模式 | 为什么致命 |
| --- | --- | --- |
| 01 | 把本地目录当共享盘 | 几个克隆互不相通，改完不推等于没改 |
| 02 | 直接 push 到 main | 未审代码和冲突一起进主干，回滚成本翻倍 |
| 03 | 交接单只在本地草稿里 | 下一棒 fetch 不到，只能从提交历史考古 |
| 04 | 把聊天记录复制粘贴当交接 | 噪声大、关键结论埋在中途，等于没交接 |
| 05 | 一张卡塞一整个功能 | 无法验收，实现席必然发散，最后谁也不敢合并 |
| 06 | 跳过验收门直接换人 | 错误被下一棒当成事实继续放大 |

**统一止损动作**：停写 → 回滚到上一次绿色提交 → 补齐任务卡 → 重新派单。

## 协议版本与兼容

- 交接单 frontmatter 带 `schema_version`；state.json 带 `schema_version`（当前 1）。
- 模板变更做兼容读取：缺字段按旧版默认值处理，不直接报错退出。
- Skill 用语义化版本；破坏性变更（状态枚举、字段名、分支约定）升主版本，新增字段升次版本。
- 当前文档版本 V1.3：新增 P5、软交接检查点、state.session 字段。
