# 车间协议与七步接力循环

## 仓库结构

```text
origin/                        # 各克隆共同指向的唯一远端
├─ main                        # 集成分支：只接受合并，开保护规则
├─ agent/T-014                 # 一卡一分支：分支存在 = 已被认领
└─ agent/T-014-review          # 可选：评审留痕分支（团队要求时）

任一份克隆内的结构（各份一致，靠 git 同步）
repo/
├─ AGENTS.md                   # 技术栈、三条验收命令、目录约定、禁止事项
├─ .agent/
│  ├─ tasks/T-014.md           # 任务卡：目标 + 验收命令 + 允许改动范围
│  ├─ handoffs/T-014.md        # 交接单：现状 + 已做 + 未做 + 下一动作
│  ├─ log.md                   # 只追加流水账：谁、何时、推到哪个分支
│  └─ state.json               # 当前阶段、认领分支、阻塞项
└─ src/                        # 业务代码：只在本卡分支上改
```

## 五条前提

1. `AGENTS.md` 跟代码一起进仓库：随 fetch 同步，不是谁的私人笔记。
2. 任务卡写在 main（或专门派单分支）并推送，其他人 fetch 后才知道有这张卡。
3. 任务卡只写一个可验收目标；写不出验收命令的需求回炉重写。
4. 改动只在 `agent/T-xxx` 分支；main 开保护：禁直推、必须构建通过、至少一次评审。
5. 交接单写明分支名与最后一次提交号，下一棒用它定位，不靠猜。

## 一棒要跑的命令

```bash
# 01 先对齐远端
git fetch --all --prune
git switch main && git pull --ff-only

# 02 建分支并推送，才算认领
git switch -c agent/T-014
git push -u origin agent/T-014

# 03 在自己的克隆里做完并自检
pnpm build && pnpm test      # 换成 AGENTS.md 里的真实命令
git status --short

# 04 交接单和代码一起推
git add .agent/handoffs/T-014.md src/
git commit -m "feat(x): … [T-014]"
git push

# 05 rebase 后合并回主干
git fetch && git switch agent/T-014
git rebase origin/main
git switch main && git merge --no-ff agent/T-014
```

> 实际执行优先用 `scripts/relay-*.sh`，它们把顺序、检查项和 state/log 更新固化下来。

## 总线纪律

- 本地目录不共享，远端才共享：任何要交接的东西先 commit，再 push。
- 认领用远程分支实现，不需要锁服务；push 成功才算占到卡。
- 顾问席可以只读，但它的卡和评审结论同样要推上去。
- 禁止 force push；push 被拒先 fetch + rebase 再重试。
- 一张卡一个分支；要并行就拆卡、拆文件，不能两个克隆改同一段代码。

## 七步接力（每步的产出）

| # | 步骤 | 席位 | 产出 | 规则 |
| --- | --- | --- | --- | --- |
| 01 | 派单 | 产品席 + 人 | 已推送的 `.agent/tasks/T-014.md` | 一卡一个可验收目标 |
| 02 | 同步 | 任一实现席 | fetch 后的远端分支列表 | 先看有没有人认领 |
| 03 | 认领 | 实现席 | `origin/agent/T-014` | push 成功才算占到 |
| 04 | 勘察 | 实现席 | 3 行结论：现状 / 要改的文件 / 风险 | 先读后写，确认再动手 |
| 05 | 实现 + 自检 | 实现席 | 本分支绿色提交 | 全绿才允许交接 |
| 06 | 交接 | 实现席 | 已推送的 `.agent/handoffs/T-014.md` | 别留在本地 |
| 07 | 评审合并 | 评审席 + 人 | review 结论 + main 合并提交 | 评审只读 diff，不直接改码 |

七个席位不必都上；最少两人即可跑通。人越多，越依赖第 06 步那张纸的质量。

## 中途换人：换棒，不换分支

判断标准只有一个：**这一棒能不能交出一个可验收的增量**。能就拆卡，不能就续棒。

| 情形 | 处置 | 分支 | 交接物 |
| --- | --- | --- | --- |
| 只是换执行者，边界不变 | 续棒 | 同一条 `agent/T-014` 追加提交，不新建分支、不复制卡 | WIP 交接单，写清最后一次提交号 |
| 剩余部分能独立验收 | 拆卡 | 原卡收口后合并进 main，再从最新 main 拉 `agent/T-015` | 原卡关闭说明 + 新卡（含新验收命令） |
| 方向错了或卡本身不成立 | 废卡 | 分支打 tag 留档后丢弃，不合并；从 main 重新开卡 | 一句话写清为什么废 |

```bash
# 第一棒：半成品必须先推上去（不合并）
git add -A
git commit -m "wip(T-014): 做完 X，卡在 Y"
git push

# 第二棒：接同一条分支，先看最后一棒停在哪
git fetch --prune
git switch agent/T-014 && git pull --ff-only
git log --oneline -3

# 收口后照常回主干
git switch main && git pull --ff-only
git merge --no-ff agent/T-014
```

## WIP 交接单五格

1. **现状**：一句话说清当前能不能构建、能不能跑。
2. **已完成**：列到提交号，别写「差不多了」。
3. **卡在哪**：贴失败命令的原始输出，不要转述。
4. **下一动作**：只写一个可执行动作，不写方向。
5. **不要碰**：明确禁止改的文件与原因。

## 换人五条禁令

- 同一张卡不要在两个克隆各开一条分支，双写必然冲突。
- 不要把未提交的改动贴进聊天窗口，换台机器就丢了。
- 不要用 `git stash` 交接，它只存在那台机器上。
- 不要为了换人把红的分支合进 main，先修绿或先回退。
- 不要把拆卡当默认动作，拆一次就多丢一次上下文。
